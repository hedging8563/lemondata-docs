## 概要

TokenLabは複数のAPIフォーマットを提供しており、一般的なコーディングツール、SDK、フレームワークが最小限のグルーコードで統合できるようになっています。

このページは、マーケティング用のマトリックスよりも意図的に範囲を絞っています。

- **Supported (サポート済み)**: 具体的なセットアップ手順が文書化されており、TokenLabがその手順で期待されるプロトコル形式を提供していることを意味します。
- **Strong native path (強力なネイティブパス)**: そのプロトコルファミリーに対して、リポジトリが直接的なアダプターやリクエスト形式のエビデンスを備えていることを意味します。
- **Best-effort (ベストエフォート)**: 統合は可能ですが、アップストリームのクライアントがこのカスタムゲートウェイワークフローを安定したコントラクトとして扱っていないことを意味します。

<Note>
  サポートされていないフィールドの扱いは一貫していません。互換性ルートでは、一部のフィールドは無視されるか正規化されます。`/v1/responses` では、リクエストされた動作を保証できないルートにおいて、明示的な `400` または `503` エラーが返される場合があります。
</Note>

## サポートされているAPIフォーマット

| エンドポイント | フォーマット | ユースケース |
|----------|--------|----------|
| `/v1/chat/completions` | OpenAI Chat | ユニバーサルな互換性 |
| `/v1/responses` | OpenAI Responses | ステートフルな会話 |
| `/v1/messages` | Anthropic Messages | Claudeネイティブ機能 |
| `/v1beta/models/:model:generateContent` | Google Gemini | Geminiネイティブ機能 |

## IDE & CLI 互換性

### 文書化されたツールパス

| ツール | サポートレベル | フォーマット | 備考 |
|------|---------------|--------|-------|
| **Cursor** | 制限付きサポート | OpenAI互換 | BYOK標準チャット/エディタフローで動作しますが、Tab CompletionのようなCursor管理機能の代替にはなりません |
| **Claude Code CLI** | 強力なネイティブパス | Anthropic | thinkingおよび `tool_choice` のアダプター対応を含むネイティブな `/v1/messages` ルート |
| **Codex CLI** | モデル/パス制限付きサポート | OpenAI Responses | `/v1/responses` をCodex固有ワークフロー向けの高度なパスとして扱ってください。Responses専用フィールドの一部は、すべてのモデルやルーティングパスで保証されているわけではありません |
| **Gemini CLI** | ベストエフォート / 実験的 | Gemini | カスタムTokenLabベースURLフローは、公式のGemini CLI統合ではありません |
| **OpenCode** | サポート済み | OpenAI互換 | デフォルトではOpenAI互換プロバイダーを使用し、明示的に必要な場合のみResponsesベースのプロバイダーに切り替えてください |
| **OpenHands** | サポート済み | OpenAI互換 | `openai/<model>` とTokenLabの `/v1` ベースURLを使用して、LiteLLM/OpenAI互換パスを使用してください |

<Note>
  他のOpenAI互換エディタやエージェントツールも、同じベースURLパターンで動作することがよくあります。本番環境で使用する前に、ツール独自のカスタムプロバイダーサポートを確認してください。
</Note>

### 設定例

<Tabs>
  <Tab title="Cursor">

    - OpenAIフォーマット: `{ type: "function", function: { name, parameters } }`
    - Anthropicフォーマット: `{ name, input_schema }` (typeフィールドなし)
  </Tab>

  </Tab>
  <Tab title="Aider">

    ```bash
    export OPENAI_BASE_URL="https://api.tokenlab.sh/v1"

    ```
  </Tab>
</Tabs>

## SDK 互換性

### 文書化されたSDK & フレームワークパス

| SDK / フレームワーク | 言語 | サポートレベル | 備考 |
|-----------------|----------|---------------|-------|
| **OpenAI SDK** | Python/JS/Go | サポート済みコアパス | `/v1` Chat CompletionsおよびEmbeddingsの互換パス。プロバイダー固有の動作にはネイティブプロバイダーのルートを使用し、Responses専用フィールドがすべてのモデルで動作すると想定しないでください |
| **Anthropic SDK** | Python/JS | 強力なネイティブパス | ツール、thinking、プロンプトキャッシングのエビデンスを備えたネイティブMessagesルート |

| **LangChain** | Python/JS | サポート済み標準サーフェス | `ChatOpenAI` および `OpenAIEmbeddings` が対象範囲です。ベンダーネイティブの拡張機能は対象外です |
| **LlamaIndex** | Python | `OpenAILike` 経由でサポート | TokenLabのようなサードパーティゲートウェイには、組み込みのOpenAIクラスではなく `OpenAILike` を使用してください |
| **OpenAI Agents SDK** | Python | サポート済みチャット補完パス | `AsyncOpenAI(base_url="https://api.tokenlab.sh/v1")` と `OpenAIChatCompletionsModel` を使用してください。ネイティブResponsesの動作は選択したモデルとルートに依存します |
| **AutoGen** | Python | サポート済みカスタムエンドポイントパス | `base_url: https://api.tokenlab.sh/v1` を指定して `OpenAIChatCompletionClient` を使用してください |
| **Semantic Kernel** | .NET | サポート済みカスタムエンドポイントパス | OpenAIチャット補完コネクタのカスタムエンドポイントを使用し、`https://api.tokenlab.sh/v1` を指定してください |
| **CrewAI** | Python | サポート済みカスタムエンドポイントパス | `OPENAI_API_BASE` または `LLM(base_url=...)` をTokenLabの `/v1` エンドポイントに設定してください |
| **Pydantic AI** | Python | サポート済みOpenAI互換プロバイダーパス | `OpenAIProvider(base_url="https://api.tokenlab.sh/v1")` を指定して `OpenAIChatModel` を使用してください |
| **DSPy** | Python | サポート済みカスタムエンドポイントパス | `dspy.LM("openai/<model>", api_base="https://api.tokenlab.sh/v1")` を使用してください |
| **Langflow** | Python / Web | 制限付きサポート | OpenAIコンポーネントの **OpenAI API Base** フィールドにTokenLabの `/v1` エンドポイントを指定してください |
| **Dify** | - | 制限付きサポート | OpenAIプロバイダーおよびチャット補完指向のフローが対象です。Codex固有のResponsesやWebSocket動作には適していません |
| **Flowise** | Web / Node | 制限付きサポート | 利用可能な場合はTokenLabチャットノードを使用するか、`https://api.tokenlab.sh/v1` を指定したChatOpenAI互換ノードを使用してください |
| **Mem0** | Python | サポート済みカスタムエンドポイントパス | OpenAIプロバイダーを維持し、`openai_base_url` をTokenLabの `/v1` エンドポイントに設定してください |
| **Agno** | Python | サポート済みパス | 利用可能な場合はTokenLabモデルラッパーを使用するか、OpenAI互換ベースURLパスを使用してください |
| **Promptfoo** | CLI / Node | サポート済みパス | `apiBaseUrl: https://api.tokenlab.sh/v1` を指定してOpenAIチャットまたはResponsesプロバイダーを使用してください |
| **Portkey Gateway** | Gateway | サポート済みパス | OpenAI互換チャットおよびResponsesトラフィックのアップストリームプロバイダーとしてTokenLabを使用してください |
| **Helicone** | Gateway / Observability | サポート済み可観測性パス | `Helicone-Target-Url: https://api.tokenlab.sh` を指定して、OpenAI互換リクエストをHelicone Gateway経由でルーティングしてください |
| **Phoenix** | Observability | サポート済みトレーシングパス | TokenLabの `/v1` ベースURLで設定されたOpenAI SDKクライアントを自動計測してください |

| **Open WebUI** | Web Chat | サポート済みチャットアプリパス | OpenAI互換API接続としてTokenLabを追加し、モデルリストを更新してください |

## Chat Completions パラメータ

### コアパラメータ

| パラメータ | 型 | 説明 |
|-----------|------|-------------|
| `model` | string | モデル識別子 (必須) |
| `messages` | array | 会話メッセージ (必須) |
| `max_tokens` | integer | 最大出力トークン数 |
| `temperature` | number | サンプリング温度 (0-2) |
| `top_p` | number | 核サンプリング (0-1) |
| `stream` | boolean | ストリーミングの有効化 |

### ツール呼び出し

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get weather for a location",
        "parameters": {
          "type": "object",
          "properties": {
            "location": { "type": "string" }
          }
        },
        "strict": true
      }
    }
  ],
  "tool_choice": "auto",
  "parallel_tool_calls": true
}
```

### ツール選択オプション

| フォーマット | 例 | 説明 |
|--------|---------|-------------|
| String | `"auto"`, `"none"`, `"required"` | 単純な選択 |
| OpenAI Object | `{ "type": "function", "function": { "name": "fn" } }` | 特定の関数を強制 |
| Anthropic Object | `{ "type": "tool", "name": "fn", "disable_parallel_tool_use": true }` | Anthropicネイティブフォーマット |

### 高度なパラメータ

| パラメータ | 型 | 説明 |
|-----------|------|-------------|
| `stream_options` | object | Chat Completionsのみ: トークンカウント用に `{ include_usage: true }` を指定 |
| `reasoning_effort` | string | 推論対応GPT-5モデル向け `"low"`, `"medium"`, `"high"` |
| `service_tier` | string | `"auto"` または `"default"` |
| `seed` | integer | 決定論的出力 |
| `logprobs` | boolean | ログ確率を返す |
| `top_logprobs` | integer | 上位ログ確率の数 (0-20) |
| `logit_bias` | object | トークンバイアスマップ (-100〜100) |
| `frequency_penalty` | number | 繰り返しペナルティ (-2〜2) |
| `presence_penalty` | number | トピックペナルティ (-2〜2) |
| `stop` | string/array | 停止シーケンス |
| `n` | integer | 補完数 (1-128) |
| `user` | string | 追跡用ユーザー識別子 |

### OpenAI 高度な機能

| パラメータ | 型 | 説明 |
|-----------|------|-------------|
| `modalities` | array | マルチモーダル用 `["text", "audio"]` |
| `audio` | object | 音声出力設定 (音声、フォーマット) |
| `prediction` | object | 高速補完のための予測出力 |
| `metadata` | object | 追跡用キーバリューペア |
| `store` | boolean | 後で取得するために保存 |

### プロバイダー固有オプション

```json
{
  "anthropic_options": {
    "thinking": {
      "type": "enabled",
      "budget_tokens": 10000
    },
    "prompt_caching": true
  },
  "google_options": {
    "safety_settings": [...],
    "google_search": true,
    "code_execution": true
  }
}
```

## ストリーミング

Chat CompletionsやResponsesを含む `stream: true` を公開する生成エンドポイントは、Server-Sent Events (SSE) を使用します：

```bash
# Chat Completions
curl https://api.tokenlab.sh/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -d '{"model": "gpt-4o", "messages": [...], "stream": true}'

# Chat Completionsの利用状況追跡
-d '{"...", "stream_options": {"include_usage": true}}'
```

## エラーハンドリング

TokenLabはOpenAI互換のエラーレスポンスを返します：

```json
{
  "error": {
    "message": "Invalid API key",
    "type": "invalid_api_key",
    "code": "invalid_api_key"
  }
}
```

詳細は [エラーハンドリングガイド](/guides/error-handling) を参照してください。

## ベストプラクティス

<AccordionGroup>
  <Accordion title="不明なパラメータにはパススルーを使用する">
    不明なパラメータは、選択されたパブリックルートとモデルがそれらをサポートしている場合にのみ転送されます。
  </Accordion>

  <Accordion title="stream_options.include_usageはChat Completionsでのみ使用する">
    Chat Completionsのストリーミングでは、正確なトークンカウントのために `stream_options.include_usage` を有効にしてください。Responsesには独自のストリーミングコントラクトがあり、このChat専用オプションは公開されていません。
  </Accordion>

  <Accordion title="適切なtool_choiceフォーマットを使用する">
    SDKが期待するフォーマットに合わせてください。TokenLabはOpenAIとAnthropicの両方のフォーマットを受け入れます。
  </Accordion>
</AccordionGroup>
