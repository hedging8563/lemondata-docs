## 概要

[Cursor](https://cursor.sh) は bring-your-own-key (BYOK) プロバイダーをサポートしていますが、カスタム API key が機能するのは標準 chat model のみです。ここでは LemonData を、あらゆる Cursor model 機能を完全に置き換えるものとしてではなく、chat スタイルのエディタワークフロー向けの OpenAI 互換 endpoint として使用してください。

## 設定

1. Cursor Settings (`Cmd/Ctrl + ,`) を開きます
2. 左側のサイドバーで **Models** に移動します
3. **OpenAI API Key** セクションまでスクロールします
4. LemonData API key を入力します
5. **Override OpenAI Base URL** を有効にします
6. Base URL を次のように設定します:

```
https://api.lemondata.cc/v1
```

<Warning>
Cursor のカスタム API key は標準 chat model にのみ適用されます。Tab Completion やその他の Cursor 管理の特化機能は、引き続き Cursor の組み込みプロバイダーを使用します。
</Warning>

<Warning>
Cursor のカスタム API key フローは、標準 chat model にのみ適用されます。Tab Completion や一部の reasoning 固有フローなど、Cursor 管理の特化 model を必要とする機能は、引き続き Cursor の組み込みプロバイダーを使用します。また、Cursor は、最終的な prompt の組み立てのために request が引き続きその backend を通過することも明記しています。
</Warning>

## Model の選択

設定後は、LemonData を通じて提供される標準 chat model を優先して使用してください:

### コーディング向けの推奨 Model

| Model | 最適な用途 |
|-------|----------|
| `gpt-5.4` | 一般的なコーディング、デバッグ、chat |
| `gpt-5-mini` | 高速な編集と軽量な prompt |

## 最も適した用途

### Chat とエディタフロー

Cursor で LemonData を使用する対象:

- コードの説明
- バグ修正
- リファクタリングの提案
- ドキュメント生成

### Cursor 管理 model のままになるもの

これらの機能は、LemonData endpoint へ確実には切り替わりません:

- Tab Completion
- 特化された非標準 chat model
- Cursor が組み込み model でのみ有効化する provider 固有機能

## トラブルシューティング

<AccordionGroup>
  <Accordion title="Model が表示されない">
    Cursor は model と provider の状態をキャッシュします。API key と base URL を設定した後、Cursor を再起動してください。
  </Accordion>

  <Accordion title="BYOK モードで Model がサポートされていない">
    カスタム API key は標準 chat model でのみ機能します。model が Cursor の特化インフラストラクチャを使用している場合は、`gpt-5.4` などの標準 chat model に切り替えてください。
  </Accordion>

  <Accordion title="認証エラー">
    API key が正しく、十分な残高があることを確認してください。
  </Accordion>

  <Accordion title="LemonData を有効にした後、別の provider が動作しなくなった">
    Cursor の BYOK 設定は他の provider フローに影響を与える可能性があります。OpenAI base URL override を有効にした後で別の model パスが動作しなくなった場合は、override を無効にして Cursor を再起動してください。
  </Accordion>
</AccordionGroup>
