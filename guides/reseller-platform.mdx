## Overview

The reseller console is a branded operating surface for a partner organization. Operators manage local downstream customer records, create API keys under the partner organization, set model listing multipliers, and reconcile usage.

Downstream customer records are local reseller records. They are not main-site user accounts and they do not sign in to the main dashboard. They use the API keys created for them.

## Operating Model

| Area | Owner system | Notes |
|------|-----------------|-------|
| Partner settlement balance | Main organization balance | API key spend and spend caps consume the partner organization balance. |
| Customer operating balance | Reseller console | This is an internal ledger for reseller operations and customer accounting. It does not create upstream credit. |
| API keys | Management API | Keys are created under the partner organization and bound to a local customer record. |
| Model availability | Reseller model center | Listed models are synced into active key allowlists. |
| Retail price | Model official price × retail multiplier | The public model page shows final USD retail prices for downstream customers. |
| Settlement terms | Partner settlement multiplier | Private reseller tokens can read settlement multipliers, not upstream cost or platform profit. |

## Recommended Workflow

1. Create or update the local customer record in the reseller console.
2. Adjust the customer's operating balance if you use internal prepaid accounting.
3. Create an API key for that customer and set a positive USD settlement spend cap.
4. Use the model center to list models and set retail multipliers. A multiplier of `1` means provider official price; `0.7` means 70% of provider official price.
5. Review usage, billing, and margin reports from reseller snapshots.
6. Suspend a customer when needed. Active keys are disabled with the customer; restoring the customer does not automatically restore keys.

## Management API Boundaries

Use a management token only from your server or console backend:

```bash
Authorization: Bearer mt-your-management-token
```

The regular Management API supports organization balance, key creation, key updates, and key-level usage or billing. Reseller settlement multipliers use a separate private capability:

```text
reseller_settlement:read
```

Dashboard-created ordinary management tokens do not receive this capability automatically.

## Pricing Boundaries

The reseller console and public model pages should not show upstream execution cost, platform profit, gross profit, partner pool, or legacy profit-share fields.

Use these terms consistently:

| Term | Meaning |
|------|---------|
| Official price | Provider official model price used as the retail basis. |
| Retail multiplier | The reseller's customer price multiplier. Range: `0` to `1`. |
| Settlement multiplier | The partner's private settlement multiplier. |
| Margin multiplier | `retailMultiplier - settlementMultiplier`; it can be negative if you sell below settlement cost. |
| Settlement spend cap | The USD cap enforced on the partner organization key. |
| Operating balance | Reseller-owned customer ledger balance for operations and reconciliation. |

## What Is Not Supported

- No agent layer or agent profit sharing.
- No reseller wallet separate from the partner organization balance.
- No downstream main-site user lifecycle.
- No Management API endpoint for platform profit or upstream cost.
- No public OpenAPI entry for private reseller settlement terms.
