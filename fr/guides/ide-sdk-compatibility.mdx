## Vue d’ensemble

LemonData expose plusieurs formats d’API afin que les coding tools, SDK et frameworks courants puissent s’intégrer avec peu de glue code.

Cette page est volontairement plus stricte qu’une simple matrice marketing.

- **Pris en charge** signifie que nous documentons un chemin de configuration concret et que LemonData expose la forme de protocole attendue par ce chemin.
- **Chemin natif fort** signifie que le dépôt contient aussi des preuves directes au niveau adapter / request-format pour cette famille de protocoles.
- **Best-effort** signifie que l’intégration peut fonctionner, mais que le client amont ne considère pas ce workflow de gateway personnalisée comme un contrat stable.

<Note>
  Les champs non pris en charge ne sont pas traités de manière uniforme. Sur les routes de compatibilité, certains champs sont ignorés ou normalisés. Sur les routes Responses natives, des erreurs explicites `400` ou `503` peuvent être renvoyées si le modèle choisi ou le channel routé ne prend pas en charge le passthrough requis.
</Note>

## Formats d’API pris en charge

| Endpoint | Format | Cas d’usage |
|----------|--------|----------|
| `/v1/chat/completions` | OpenAI Chat | Compatibilité universelle |
| `/v1/responses` | OpenAI Responses | Conversations avec état |
| `/v1/messages` | Anthropic Messages | Fonctionnalités natives de Claude |
| `/v1beta/models/:model:generateContent` | Google Gemini | Fonctionnalités natives de Gemini |

## Compatibilité IDE & CLI

### Chemins d’outils documentés

| Outil | Niveau de support | Format | Notes |
|------|-------------------|--------|-------|
| **Cursor** | Pris en charge avec limites | OpenAI-compatible | Adapté aux flux BYOK standard de chat / édition, sans prétendre remplacer les fonctions gérées par Cursor comme Tab Completion |
| **Claude Code CLI** | Chemin natif fort | Anthropic | Route native `/v1/messages` avec preuves adapter pour thinking et `tool_choice` |
| **Codex CLI** | Pris en charge, mais dépendant du modèle / channel | OpenAI Responses | Idéalement configuré sur `/v1/responses`; certains champs Responses-native dépendent du passthrough natif du modèle / channel |
| **Gemini CLI** | Expérimental / best-effort | Gemini | Le workflow de base URL personnalisée avec LemonData n’est pas un contrat upstream stable |
| **OpenCode** | Pris en charge | OpenAI-compatible | Utiliser d’abord un provider OpenAI-compatible, puis ne passer à un provider Responses qu’en cas de besoin explicite |

<Note>
  D’autres éditeurs et agent tools OpenAI-compatible fonctionnent souvent avec le même schéma de base URL, mais ce dépôt ne maintient pas aujourd’hui de régressions dédiées pour Windsurf, Aider, Continue.dev, Cline/Roo Code ou GitHub Copilot.
</Note>

### Exemples de configuration

<Tabs>
  <Tab title="Cursor">
    ```
    Base URL: https://api.lemondata.cc/v1
    API Key: sk-your-lemondata-key
    ```
    Cursor utilise en interne un format d’outil de type Anthropic. LemonData prend en charge les deux :
    - Format OpenAI : `{ type: "function", function: { name, parameters } }`
    - Format Anthropic : `{ name, input_schema }` (sans champ type)
  </Tab>
  <Tab title="Claude Code">
    ```bash
    export ANTHROPIC_BASE_URL="https://api.lemondata.cc"
    export ANTHROPIC_API_KEY="sk-your-lemondata-key"
    ```
  </Tab>
  <Tab title="OpenCode">
    ```bash
    export OPENAI_API_KEY="sk-your-lemondata-key"
    export LOCAL_ENDPOINT="https://api.lemondata.cc/v1"
    ```
  </Tab>
  <Tab title="Aider">
    ```bash
    export OPENAI_API_KEY="sk-your-lemondata-key"
    export OPENAI_BASE_URL="https://api.lemondata.cc/v1"
    aider --model gpt-5.4
    ```
  </Tab>
</Tabs>

## Compatibilité SDK

### Chemins SDK / frameworks documentés

| SDK / Framework | Langage | Niveau de support | Notes |
|-----------------|---------|-------------------|-------|
| **OpenAI SDK** | Python/JS/Go | Chemin cœur pris en charge | Documente Chat Completions, Embeddings et les workflows Responses courants ; certains champs Responses-native-only dépendent du passthrough model / channel |
| **Anthropic SDK** | Python/JS | Chemin natif fort | Route Messages native avec preuves directes pour tools, thinking et prompt caching |
| **Vercel AI SDK** | TypeScript | Modèle d’intégration recommandé | Préférer `@ai-sdk/openai-compatible`, et n’utiliser `@ai-sdk/openai` qu’en cas de besoin Responses-native explicite |
| **LangChain** | Python/JS | Surface standard prise en charge | Le périmètre visé couvre `ChatOpenAI` et `OpenAIEmbeddings` ; les extras vendor-native sont hors périmètre |
| **LlamaIndex** | Python | Pris en charge via `OpenAILike` | Pour les gateways tiers comme LemonData, utiliser `OpenAILike` plutôt que les classes OpenAI intégrées |
| **Dify** | - | Pris en charge avec limites | Le chemin attendu passe par le provider OpenAI et des flux orientés chat-completions ; pas de garantie pour les comportements Codex-specific Responses / WebSocket |

## Paramètres Chat Completions

### Paramètres principaux

| Parameter | Type | Description |
|-----------|------|-------------|
| `model` | string | Identifiant du modèle (obligatoire) |
| `messages` | array | Messages de conversation (obligatoire) |
| `max_tokens` | integer | Nombre maximal de tokens de sortie |
| `temperature` | number | Température d’échantillonnage (0-2) |
| `top_p` | number | Échantillonnage nucleus (0-1) |
| `stream` | boolean | Activer le streaming |

### Appel d’outils

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get weather for a location",
        "parameters": {
          "type": "object",
          "properties": {
            "location": { "type": "string" }
          }
        },
        "strict": true
      }
    }
  ],
  "tool_choice": "auto",
  "parallel_tool_calls": true
}
```

### Options de Tool Choice

| Format | Example | Description |
|--------|---------|-------------|
| String | `"auto"`, `"none"`, `"required"` | Sélection simple |
| OpenAI Object | `{ "type": "function", "function": { "name": "fn" } }` | Forcer une fonction spécifique |
| Anthropic Object | `{ "type": "tool", "name": "fn", "disable_parallel_tool_use": true }` | Format natif Anthropic |

### Paramètres avancés

| Parameter | Type | Description |
|-----------|------|-------------|
| `stream_options` | object | `{ include_usage: true }` pour les décomptes de tokens |
| `reasoning_effort` | string | `"low"`, `"medium"`, `"high"` pour les modèles GPT-5 avec raisonnement activé |
| `service_tier` | string | `"auto"` ou `"default"` |
| `seed` | integer | Sorties déterministes |
| `logprobs` | boolean | Retourner les probabilités logarithmiques |
| `top_logprobs` | integer | Nombre de top logprobs (0-20) |
| `logit_bias` | object | Table de biais des tokens (-100 à 100) |
| `frequency_penalty` | number | Pénalité de répétition (-2 à 2) |
| `presence_penalty` | number | Pénalité de sujet (-2 à 2) |
| `stop` | string/array | Séquences d’arrêt |
| `n` | integer | Nombre de complétions (1-128) |
| `user` | string | Identifiant utilisateur pour le suivi |

### Fonctionnalités avancées OpenAI

| Parameter | Type | Description |
|-----------|------|-------------|
| `modalities` | array | `["text", "audio"]` pour le multimodal |
| `audio` | object | Configuration de sortie audio (voice, format) |
| `prediction` | object | Sortie prédite pour une complétion plus rapide |
| `metadata` | object | Paires clé-valeur pour le suivi |
| `store` | boolean | Stocker pour une récupération ultérieure |

### Options spécifiques au provider

```json
{
  "anthropic_options": {
    "thinking": {
      "type": "enabled",
      "budget_tokens": 10000
    },
    "prompt_caching": true
  },
  "google_options": {
    "safety_settings": [...],
    "google_search": true,
    "code_execution": true
  }
}
```

## Paramètres de l’API Responses

### Paramètres principaux

| Parameter | Type | Description |
|-----------|------|-------------|
| `model` | string | Identifiant du modèle |
| `input` | string/array | Contenu d’entrée |
| `instructions` | string | Instructions système |
| `max_output_tokens` | integer | Nombre maximal de tokens de sortie |
| `previous_response_id` | string | Continuer la conversation |

### Paramètres avancés

| Parameter | Type | Description |
|-----------|------|-------------|
| `truncation_strategy` | string | `"auto"` ou `"disabled"` |
| `include` | array | `["reasoning.encrypted_content"]` |
| `reasoning_effort` | string | Pour les modèles de raisonnement |
| `service_tier` | string | Niveau de priorité |

### Format d’outil

Prend en charge les formats d’outil OpenAI et Anthropic :

```json
// OpenAI format
{ "type": "function", "name": "fn", "parameters": {...} }

// Anthropic format (Cursor compatibility)
{ "name": "fn", "input_schema": {...} }
```

## Paramètres de l’API Gemini

### Paramètres principaux

| Parameter | Type | Description |
|-----------|------|-------------|
| `contents` | array | Contenu de la conversation |
| `systemInstruction` | object | Prompt système |
| `generationConfig` | object | Paramètres de génération |

### Outils

```json
{
  "tools": [{
    "functionDeclarations": [{
      "name": "search",
      "description": "Search the web",
      "parameters": {...}
    }],
    "codeExecution": {},
    "googleSearch": {}
  }],
  "toolConfig": {
    "functionCallingConfig": {
      "mode": "AUTO"
    }
  }
}
```

### Paramètres de sécurité

```json
{
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_MEDIUM_AND_ABOVE"
    }
  ]
}
```

### Paramètres supplémentaires

| Parameter | Type | Description |
|-----------|------|-------------|
| `cachedContent` | string | Référence au contenu en cache |
| `responseMimeType` | string | `"text/plain"` ou `"application/json"` |
| `responseSchema` | object | Schéma JSON pour une sortie structurée |

## Streaming

Tous les endpoints prennent en charge le streaming Server-Sent Events (SSE) :

```bash
# Chat Completions
curl https://api.lemondata.cc/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -d '{"model": "gpt-4o", "messages": [...], "stream": true}'

# With usage tracking
-d '{"...", "stream_options": {"include_usage": true}}'
```

## Gestion des erreurs

LemonData renvoie des réponses d’erreur compatibles OpenAI :

```json
{
  "error": {
    "message": "Invalid API key",
    "type": "invalid_api_key",
    "code": "invalid_api_key"
  }
}
```

Voir le [Guide de gestion des erreurs](/guides/error-handling) pour plus de détails.

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Utiliser le passthrough pour les paramètres inconnus">
    Tous les schémas utilisent `.passthrough()` - les paramètres inconnus sont transmis aux fournisseurs en amont.
  </Accordion>

  <Accordion title="Préférer stream_options pour une facturation précise">
    Activez `stream_options.include_usage` pour obtenir des décomptes de tokens précis dans les réponses en streaming.
  </Accordion>

  <Accordion title="Utiliser le format de tool_choice approprié">
    Faites correspondre le format attendu par votre SDK. LemonData accepte les formats OpenAI et Anthropic.
  </Accordion>
</AccordionGroup>
