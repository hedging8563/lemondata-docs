## Aperçu

L'API de gestion vous permet de gérer les clés API de l'organisation et de consulter l'utilisation et la facturation d'une clé donnée sans utiliser une clé API d'inférence standard.

Utilisez un jeton de gestion depuis la page **Settings** de votre Dashboard :

```bash
Authorization: Bearer mt-your-management-token
```

<Warning>
Les jetons de gestion ne sont pas des clés API d'inférence. Utilisez `mt-...` pour `/v1/management/*` et `sk-...` pour les endpoints d'inférence comme `/v1/responses`.
</Warning>

## Endpoints disponibles

| Endpoint | Method | Description |
|----------|--------|------|
| `/v1/management/api-keys` | GET | Liste les clés API utilisateur de l'organisation courante |
| `/v1/management/api-keys` | POST | Crée une nouvelle clé API utilisateur |
| `/v1/management/api-keys/{keyId}` | PATCH | Met à jour le nom, la limite d'usage, les modèles autorisés, l'expiration ou le statut |
| `/v1/management/api-keys/{keyId}/usage` | GET | Récupère les détails d'utilisation paginés pour une clé donnée |
| `/v1/management/api-keys/{keyId}/billing` | GET | Récupère les ventilations de facturation agrégées pour une clé donnée |

## Signification des champs

- nom du modèle demandé (`model`)
- fournisseur de modèle public
- `scene`
- `accessChannel` : `platform` signifie que la requête a été facturée comme une requête de plateforme ; `byok` signifie qu'elle a utilisé votre propre clé fournisseur amont
- quantité d'usage, unité de facturation et métriques de cache
- coûts et horodatages

Les réponses n'exposent que des champs publics de facturation et de reporting. Les détails de routage interne et les métadonnées du fournisseur physique restent masqués.

## Filtres

`/usage` et `/billing` prennent actuellement en charge des filtres par :

- plage de temps
- nom du modèle demandé (`model`)
- fournisseur de modèle public
- `scene`
- `accessChannel`
- pagination

## Exemple de requête complet

Commencez par lister les clés API de l'organisation accessibles avec le jeton de gestion actuel :

<RequestExample>
```bash cURL
curl "https://api.lemondata.cc/v1/management/api-keys" \
  -H "Authorization: Bearer mt-your-management-token"
```

```python Python
import requests

response = requests.get(
    "https://api.lemondata.cc/v1/management/api-keys",
    headers={"Authorization": "Bearer mt-your-management-token"}
)

data = response.json()
for key in data["data"]:
    print(key["name"], key["status"], key["used_amount"])
```

```javascript JavaScript
const response = await fetch(
  'https://api.lemondata.cc/v1/management/api-keys',
  {
    headers: {
      'Authorization': 'Bearer mt-your-management-token'
    }
  }
);

const data = await response.json();
for (const key of data.data) {
  console.log(key.name, key.status, key.used_amount);
}
```

```go Go
package main

import (
    "encoding/json"
    "fmt"
    "net/http"
)

func main() {
    req, _ := http.NewRequest("GET", "https://api.lemondata.cc/v1/management/api-keys", nil)
    req.Header.Set("Authorization", "Bearer mt-your-management-token")

    client := &http.Client{}
    resp, _ := client.Do(req)
    defer resp.Body.Close()

    var result map[string]interface{}
    json.NewDecoder(resp.Body).Decode(&result)

    fmt.Println(result["object"])
}
```

```php PHP
<?php
$ch = curl_init("https://api.lemondata.cc/v1/management/api-keys");

curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        'Authorization: Bearer mt-your-management-token'
    ]
]);

$response = curl_exec($ch);
curl_close($ch);

$data = json_decode($response, true);
foreach ($data['data'] as $key) {
    echo $key["name"] . " " . $key["status"] . " " . $key["used_amount"] . PHP_EOL;
}
```
</RequestExample>
