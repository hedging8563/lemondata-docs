---
title: "Générer du contenu"
openapi: "POST /v1beta/models/{model}:generateContent"
description: "Génère du contenu en utilisant le format de l'API Google Gemini"
---

TokenLab n’expose cette route que pour les modèles qui annoncent un contrat Gemini natif et disposent d’une route upstream du même protocole ; aucun repli vers Chat Completions n’a lieu. Les noms ProtoJSON lowerCamelCase et les noms proto originaux snake_case sont tous deux officiels et sont conservés, y compris dans les requêtes mixtes. Les champs inconnus sont transmis au mieux et l’upstream décide de leur prise en charge.
## Paramètres de chemin

<ParamField path="model" type="string" required>
  Nom du modèle (par ex., `gemini-2.5-pro`, `gemini-3.5-flash`).
</ParamField>

## Paramètres de requête

<ParamField query="key" type="string">
  Clé API (alternative à l'authentification par en-tête).
</ParamField>

## Authentification

Les points de terminaison Gemini prennent en charge plusieurs méthodes d'authentification :
- Paramètre de requête `?key=YOUR_API_KEY`
- En-tête `x-goog-api-key: YOUR_API_KEY`
- En-tête `Authorization: Bearer YOUR_API_KEY`

## Corps de la requête

<ParamField body="contents" type="array" required>
  Contenu de la conversation. Les valeurs `role` et tous les `parts` sont conservés tels qu’envoyés ; TokenLab n’effectue ni trim/lowercase, ni réécriture Base64, ni inférence MIME. `inlineData` / `inline_data` et `fileData` / `file_data` sont des graphies officielles, et TokenLab n’impose pas localement `fileData.mimeType`. Les identifiants Files ou Cache créés par TokenLab font l’objet d’un contrôle de propriété et conservent leur liaison upstream ; le fournisseur décide des autres règles média et outils.
</ParamField>

<ParamField body="systemInstruction" type="object">
  Instruction système pour le modèle.
</ParamField>

<ParamField body="generationConfig" type="object">
  Configuration native de génération. Les noms lowerCamelCase tels que `maxOutputTokens`, `candidateCount` et `thinkingConfig`, ainsi que leurs équivalents snake_case, sont acceptés sans modification. TokenLab ne supprime pas `thinkingConfig` après un échec et n’impose pas de limite locale à `candidateCount` en streaming ; l’upstream décide des plages et combinaisons.
</ParamField>

<ParamField body="safetySettings" type="array">
  Paramètres des filtres de sécurité.
</ParamField>

## Réponse

<ResponseField name="candidates" type="array">
  Candidats de contenu générés.
</ResponseField>

<ResponseField name="usageMetadata" type="object">
  Informations sur l'utilisation des tokens.
</ResponseField>

## Exemples d'entrée multimodale

Pour les requêtes multimodales Gemini, placez les médias dans `contents[].parts[]` en utilisant soit des octets inline, soit des références de fichier basées sur une URL.

Catégories de médias actuellement prises en charge dans le détails du modèle Gemini :
- image
- audio
- vidéo

Pour les médias inline, utilisez `inlineData` ou `inline_data` et transmettez les octets du fichier encodés en Base64.

Pour les médias via URL, utilisez `fileData` ou `file_data` et transmettez une URL publique en `https`.

### Exemple d'entrée image

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Veuillez décrire cette image." },
        {
          "inlineData": {
            "mimeType": "image/jpeg",
            "data": "/9j/4AAQSkZJRgABAQ..."
          }
        }
      ]
    }
  ]
}
```

### Exemple d'entrée audio

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Veuillez transcrire et résumer cet audio." },
        {
          "file_data": {
            "mime_type": "audio/mpeg",
            "file_uri": "https://example.com/sample.mp3"
          }
        }
      ]
    }
  ]
}
```

### Exemple d'entrée vidéo

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Veuillez décrire brièvement cette vidéo." },
        {
          "fileData": {
            "mimeType": "video/mp4",
            "fileUri": "https://example.com/sample.mp4"
          }
        }
      ]
    }
  ]
}
```
