---

Créez une session de vérification à courte durée de vie et redirigez votre utilisateur vers le lien H5 renvoyé. TokenLab renvoie uniquement des champs neutres : `session_id`, `h5_link`, `callback_url`, `expires_in` et `language`.

La session et le lien H5 expirent après 120 secondes. Le token de liaison est fourni uniquement par la redirection de rappel TokenLab. Lorsque le flux H5 est terminé, TokenLab redirige vers votre `callback_url` d'origine avec les paramètres de requête suivants :

| Paramètre | Signification |
|-----------|---------|
| `session_id` | ID de session de vérification TokenLab. |
| `verification_token` | Token opaque utilisé pour lier le résultat. |
| `verification_status` | `succeeded` ou `failed`. |
| `result_code` | Code de résultat pour la logique de votre application. |

Si `verification_status` est `succeeded`, appelez [Bind Real-Person Verification Result](/fr/api-reference/video/bind-real-person-verification-result). La [console de test](https://tokenlab.sh/dashboard/seedance-assets) peut être utilisée pour vérifier la gestion des callbacks avant d'intégrer le flux dans votre produit.

## Exemple de requête

```bash
curl https://api.tokenlab.sh/v1/videos/assets/visual-validation-sessions \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callback_url":"https://yourapp.example.com/seedance/callback","language":"en"}'
```

## Exemple de réponse

```json
{
  "object": "seedance.visual_validation_session",
  "session_id": "svv_abc123",
  "h5_link": "https://verify.example.com/h5?lng=en",
  "callback_url": "https://yourapp.example.com/seedance/callback",
  "expires_in": 120,
  "language": "en"
}
```
