## نظرة عامة

تتيح لك واجهة برمجة تطبيقات الإدارة إدارة مفاتيح API الخاصة بالمؤسسة واستعراض الاستخدام والفوترة لمفتاح محدد بدون استخدام مفتاح API قياسي للاستدلال.

استخدم رمز إدارة من صفحة **Settings** في لوحة التحكم:

```bash
Authorization: Bearer mt-your-management-token
```

<Warning>
رموز الإدارة ليست مفاتيح API للاستدلال. استخدم `mt-...` مع `/v1/management/*`، واستخدم `sk-...` مع نقاط استدلال مثل `/v1/responses`.
</Warning>

## نقاط النهاية المتاحة

| Endpoint | Method | الوصف |
|----------|--------|------|
| `/v1/management/api-keys` | GET | يعرض مفاتيح API الخاصة بالمستخدم داخل المؤسسة الحالية |
| `/v1/management/api-keys` | POST | ينشئ مفتاح API جديدًا للمستخدم |
| `/v1/management/api-keys/{keyId}` | PATCH | يحدّث الاسم أو حد الاستخدام أو النماذج المسموح بها أو الانتهاء أو الحالة |
| `/v1/management/api-keys/{keyId}/usage` | GET | يجلب تفاصيل الاستخدام المرقمة لصفحات لمفتاح محدد |
| `/v1/management/api-keys/{keyId}/billing` | GET | يجلب تفصيلات الفوترة المجمعة لمفتاح محدد |

## معنى الحقول

- اسم النموذج المطلوب (`model`)
- مزود النموذج العام
- `scene`
- `accessChannel`: تعني `platform` أن الطلب تم احتسابه كطلب منصة، بينما تعني `byok` أنه استخدم مفتاح مزود upstream الخاص بك
- كمية الاستخدام ووحدة الفوترة ومؤشرات الـ cache
- التكلفة والطوابع الزمنية

تُظهر الاستجابات حقول الفوترة والتقارير العامة فقط. تظل تفاصيل التوجيه الداخلية وبيانات المزوّد الفعلي مخفية.

## عوامل التصفية

تدعم `/usage` و `/billing` حاليًا التصفية حسب:

- النطاق الزمني
- اسم النموذج المطلوب (`model`)
- مزود النموذج العام
- `scene`
- `accessChannel`
- الترقيم الصفحي
