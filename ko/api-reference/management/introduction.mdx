## 개요

관리 API는 일반 추론 API 키 없이 조직 API 키를 관리하고 특정 키의 사용량 및 청구를 조회할 수 있게 해줍니다.

Dashboard의 **Settings** 페이지에서 관리 토큰을 발급받아 사용하세요:

```bash
Authorization: Bearer mt-your-management-token
```

<Warning>
관리 토큰은 추론용 API 키가 아닙니다. `mt-...` 는 `/v1/management/*` 용이고, `sk-...` 는 `/v1/responses` 같은 모델 추론 엔드포인트용입니다.
</Warning>

## 사용 가능한 엔드포인트

| Endpoint | Method | 설명 |
|----------|--------|------|
| `/v1/management/api-keys` | GET | 현재 조직의 사용자 API 키를 나열합니다 |
| `/v1/management/api-keys` | POST | 새 사용자 API 키를 생성합니다 |
| `/v1/management/api-keys/{keyId}` | PATCH | 이름, 사용 한도, 허용 모델, 만료일, 상태를 업데이트합니다 |
| `/v1/management/api-keys/{keyId}/usage` | GET | 특정 키의 페이지네이션 사용량 상세를 조회합니다 |
| `/v1/management/api-keys/{keyId}/billing` | GET | 특정 키의 집계된 청구 내역을 조회합니다 |

## 필드 설명

- 요청에 넣는 모델 이름(`model`)
- 공개 모델 벤더
- `scene`
- `accessChannel`: `platform`은 플랫폼 방식으로 과금되었다는 뜻이고, `byok`는 사용자의 업스트림 Provider 키를 사용했다는 뜻입니다
- 사용량, 과금 단위, 캐시 지표
- 비용과 타임스탬프

응답에는 공개 청구 및 리포팅 필드만 포함되며 내부 라우팅 세부 정보나 물리 채널 메타데이터는 노출되지 않습니다.

## 필터

`/usage` 와 `/billing` 는 현재 다음 조건으로 필터링할 수 있습니다:

- 기간
- 요청에 넣는 모델 이름(`model`)
- 공개 모델 벤더
- `scene`
- `accessChannel`
- 페이지네이션
