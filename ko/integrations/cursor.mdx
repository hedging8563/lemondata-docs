## 개요

[Cursor](https://cursor.sh)는 BYOK(Bring-Your-Own-Key) provider를 지원하지만, 커스텀 API 키는 표준 chat model에서만 작동합니다. 여기서는 LemonData를 모든 Cursor model 기능을 완전히 대체하는 용도가 아니라, chat 스타일 에디터 워크플로를 위한 OpenAI 호환 endpoint로 사용하세요.

## 구성

1. Cursor Settings를 엽니다 (`Cmd/Ctrl + ,`)
2. 왼쪽 사이드바에서 **Models**로 이동합니다
3. 아래로 스크롤하여 **OpenAI API Key** 섹션으로 이동합니다
4. LemonData API 키를 입력합니다
5. **Override OpenAI Base URL**을 활성화합니다
6. Base URL을 다음과 같이 설정합니다:

```
https://api.lemondata.cc/v1
```

<Warning>
Cursor 커스텀 API 키는 표준 chat model에만 적용됩니다. Tab Completion 및 기타 Cursor가 관리하는 특수 기능은 계속해서 Cursor의 내장 provider를 사용합니다.
</Warning>

<Warning>
Cursor의 커스텀 API 키 흐름은 표준 chat model에만 적용됩니다. Tab Completion 및 일부 reasoning 전용 흐름과 같이 Cursor가 관리하는 특수 model이 필요한 기능은 계속해서 Cursor의 내장 provider를 사용합니다. 또한 Cursor는 요청이 최종 prompt 구성을 위해 여전히 해당 backend를 통과한다고 명시하고 있습니다.
</Warning>

## 모델 선택

구성 후에는 LemonData를 통해 제공되는 표준 chat model을 우선적으로 사용하세요:

### 코딩용 권장 모델

| Model | 가장 적합한 용도 |
|-------|----------|
| `gpt-5.4` | 일반 코딩, 디버깅, chat |
| `gpt-5-mini` | 빠른 수정 및 가벼운 prompt |

## 가장 잘 작동하는 항목

### Chat 및 에디터 흐름

Cursor에서 LemonData를 다음 용도로 사용하세요:

- 코드 설명
- 버그 수정
- 리팩토링 제안
- 문서 생성

### Cursor 관리 모델에 남는 항목

다음 기능은 안정적으로 LemonData endpoint로 전환되지 않습니다:

- Tab Completion
- 특수한 비표준 chat model
- Cursor가 내장 model에서만 활성화하는 provider별 기능

## 문제 해결

<AccordionGroup>
  <Accordion title="모델이 표시되지 않음">
    Cursor는 model 및 provider 상태를 캐시합니다. API 키와 base URL을 구성한 후 Cursor를 다시 시작하세요.
  </Accordion>

  <Accordion title="BYOK 모드에서 지원되지 않는 모델">
    커스텀 API 키는 표준 chat model에서만 작동합니다. model이 특수한 Cursor 인프라를 사용하는 경우 `gpt-5.4`와 같은 표준 chat model로 전환하세요.
  </Accordion>

  <Accordion title="인증 오류">
    API 키가 올바르고 충분한 잔액이 있는지 확인하세요.
  </Accordion>

  <Accordion title="LemonData를 활성화한 후 다른 provider가 작동을 멈춤">
    Cursor의 BYOK 구성은 다른 provider 흐름에 영향을 줄 수 있습니다. OpenAI base URL override를 활성화한 후 다른 model 경로가 작동하지 않으면 override를 비활성화하고 Cursor를 다시 시작하세요.
  </Accordion>
</AccordionGroup>
