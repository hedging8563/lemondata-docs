## 概览

Management API 用于自动化管理**组织级 API Key 生命周期**，以及查询**单个 Key 维度的用量与账单**。

它和普通推理 API 是两套凭证体系：

- `sk-...`：用于模型推理接口，例如 `/v1/responses`
- `mt-...`：用于管理接口，即 `/v1/management/*`

管理令牌可以在 Dashboard 的 **Settings** 页面生成和轮换。

```bash
Authorization: Bearer mt-your-management-token
```

<Warning>
Management Token 不是推理 API Key，不能用于调用模型。
</Warning>

## 能做什么

当前 Management API 支持：

| Endpoint | Method | 说明 |
|----------|--------|------|
| `/v1/management/api-keys` | GET | 列出当前组织下的用户 API Key |
| `/v1/management/api-keys` | POST | 创建新的用户 API Key |
| `/v1/management/api-keys/{keyId}` | PATCH | 更新名称、额度、模型白名单、过期时间、状态 |
| `/v1/management/api-keys/{keyId}/usage` | GET | 查询该 Key 的分页用量明细 |
| `/v1/management/api-keys/{keyId}/billing` | GET | 查询该 Key 的聚合账单明细 |

## 暴露边界

Management API 只暴露**公开可理解的账单字段**，例如：

- 逻辑模型名
- 公开模型厂商
- 接口族别 `scene`
- 公开渠道维度 `platform | byok`
- token / 计费量 / 计费单位
- 缓存命中与缓存 token
- 费用与时间

不会暴露以下内部实现细节：

- `physicalModel`
- `channelId`
- `channelName`
- 实际物理路由 provider
- routing / retry / selection 细节

## 账单口径

Management API 的账单是**消费账单**，不包含以下组织级财务流水：

- 充值
- 发票
- 提现
- 退款申请

如果你只想看某把 Key 花了多少钱、打了哪些模型、命中了哪些缓存，这套接口就是对应入口。

## 筛选能力

`/usage` 与 `/billing` 目前支持按以下维度筛选：

- 时间范围
- 逻辑模型
- 公开模型厂商
- `scene`
- `accessChannel`
- 分页
