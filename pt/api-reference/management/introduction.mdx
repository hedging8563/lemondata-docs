## Visão geral

A Management API permite gerenciar API Keys da organização e consultar uso e billing por chave sem usar uma inference API key comum.

Use um management token da página **Settings** no Dashboard:

<Warning>
Management tokens são diferentes de inference API keys. Use `mt-...` para `/v1/management/*` e `sk-...` para endpoints de inferência como `/v1/responses`.
</Warning>

## Endpoints disponíveis

| Endpoint | Method | Description |
|----------|--------|-------------|
| /v1/management/api-keys | GET | List user-managed API keys in the current organization |
| /v1/management/api-keys | POST | Create a new user API key |
| /v1/management/api-keys/{keyId} | PATCH | Update name, usage limit, allowed models, expiry, or status |
| /v1/management/api-keys/{keyId}/usage | GET | Retrieve paginated usage details for a specific key |
| /v1/management/api-keys/{keyId}/billing | GET | Retrieve aggregated billing breakdowns for a specific key |

## Contrato dos filtros de uso

`GET /v1/management/api-keys/{keyId}/usage` suporta os seguintes parâmetros de query:

| Parâmetro | Tipo | Padrões / limites | Observações |
|-----------|------|------------------|-------|
| page | integer | default 1, min 1 | 1-based page number |
| limit | integer | default 50, min 1, max 100 | Page size |
| logicalModel | string | max length 100 | Requested logical model name |
| modelVendor | string | max length 100 | Public model vendor |
| scene | enum | - | chat, image, audio, video, embedding, rerank, translation, music, 3d |
| accessChannel | enum | - | platform or byok |
| startDate | string | - | Inclusive lower bound; accepts RFC3339 with timezone or YYYY-MM-DD |
| endDate | string | - | Inclusive upper bound; accepts RFC3339 with timezone or YYYY-MM-DD |

Se `startDate` e `endDate` forem enviados juntos, `startDate` deve ser menor ou igual a `endDate`.

## Contrato do corpo do API Key

### POST /v1/management/api-keys

| Campo | Tipo | Padrões / limites | Observações |
|-------|------|------------------|-------|
| name | string | obrigatório, padrão Default Key, tamanho 1-50 | Nome de exibição, normalizado no servidor |
| limitAmount | number \| null | mín. 0, máx. 100000 | null ou omitido = ilimitado, 0 = sem quota utilizável, valor positivo = teto em USD |
| models | string[] | padrão [] | Allowlist opcional de modelos lógicos |
| expiresAt | string \| null | datetime RFC3339 | null significa sem expiração |

### PATCH /v1/management/api-keys/{keyId}

| Campo | Tipo | Padrões / limites | Observações |
|-------|------|------------------|-------|
| status | enum | - | active, inactive, revoked |
| name | string | tamanho 1-50 | Nome de exibição atualizado |
| limitAmount | number \| null | mín. 0, máx. 100000 | null significa ilimitado, 0 significa sem quota |
| models | string[] | - | Allowlist de modelos lógicos atualizada |
| expiresAt | string \| null | datetime RFC3339 | null remove a expiração |

Pelo menos um campo deve ser enviado na requisição PATCH.

## Semântica de relatórios

- logicalModel se refere ao modelo lógico público solicitado pelo chamador.
- modelVendor se refere ao fornecedor público do modelo, e não à rota física oculta.
- scene é a cena pública da requisição derivada do endpoint ou do tipo de tarefa.
- accessChannel=platform significa que a requisição foi cobrada pelo canal de plataforma da LemonData.
- accessChannel=byok significa que a requisição usou sua própria chave do provedor upstream.

As respostas expõem apenas campos públicos de billing e reporting; detalhes internos de routing e metadados físicos permanecem ocultos.

## Nota sobre paginação de billing

`/usage` é paginado. `/billing` atualmente é um endpoint agregado e não retorna metadados de paginação do tipo `page` / `limit`.

## Exemplo rápido

Comece listando as API Keys disponíveis para o management token atual:

<RequestExample>
```bash cURL
curl "https://api.lemondata.cc/v1/management/api-keys" \
  -H "Authorization: Bearer mt-your-management-token"
```
</RequestExample>
