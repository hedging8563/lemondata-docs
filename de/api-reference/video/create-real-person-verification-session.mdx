---
title: "Real-Person-Verifizierungssitzung erstellen"
openapi: "POST /v1/videos/assets/visual-validation-sessions"
description: "Erstellt eine TokenLab H5-Sitzung zur Verifizierung von echten Personen."
---

Erstellen Sie eine kurzlebige Verifizierungssitzung und leiten Sie Ihren Benutzer auf den zurückgegebenen H5-Link weiter. TokenLab gibt nur neutrale Felder zurück: `session_id`, `verification_token`, `h5_link`, `callback_url`, `expires_in` und `language`.

Die Sitzung, das Token und der H5-Link laufen nach 120 Sekunden ab. Sobald der H5-Ablauf abgeschlossen ist, leitet TokenLab den Benutzer mit den folgenden Abfrageparametern an Ihre ursprüngliche `callback_url` weiter:

| Parameter | Bedeutung |
|-----------|---------|
| `session_id` | TokenLab-Verifizierungssitzungs-ID. |
| `verification_token` | Undurchsichtiges Token zur Verknüpfung des Ergebnisses. |
| `verification_status` | `succeeded` oder `failed`. |
| `result_code` | Ergebniscode für Ihre Anwendungslogik. |

Wenn `verification_status` den Wert `succeeded` hat, rufen Sie [Bind Real-Person Verification Result](/de/api-reference/video/bind-real-person-verification-result) auf. Die [Testkonsole](https://tokenlab.sh/dashboard/seedance-assets) kann verwendet werden, um die Callback-Verarbeitung zu überprüfen, bevor Sie den Ablauf in Ihr Produkt integrieren.

## Beispielanfrage

```bash
curl https://api.tokenlab.sh/v1/videos/assets/visual-validation-sessions \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callback_url":"https://yourapp.example.com/seedance/callback","language":"en"}'
```

## Beispielantwort

```json
{
  "object": "seedance.visual_validation_session",
  "session_id": "svv_abc123",
  "verification_token": "svvt_def456",
  "h5_link": "https://verify.example.com/h5?lng=en",
  "callback_url": "https://yourapp.example.com/seedance/callback",
  "expires_in": 120,
  "language": "en"
}
```
