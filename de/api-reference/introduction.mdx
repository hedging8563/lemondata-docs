## Übersicht

Die LemonData-API ist **OpenAI-kompatibel**, was bedeutet, dass Sie das offizielle OpenAI-SDK mit einer einfachen Änderung der Basis-URL verwenden können. Wir unterstützen auch native **Anthropic**- und **Gemini**-Anfrageformate.

## Basis-URL

```
https://api.lemondata.cc
```

## Authentifizierung

Alle API-Endpunkte erfordern eine Authentifizierung mittels Bearer-Token:

```bash
Authorization: Bearer sk-your-api-key
```

Holen Sie sich Ihren API-Key im [Dashboard](https://lemondata.cc/dashboard).

<Warning>
**Über den interaktiven Playground**: Der Playground auf dieser Dokumentationsseite dient nur zu Demonstrationszwecken und unterstützt die Eingabe von API-Keys nicht. Um die API zu testen, verwenden Sie bitte:
- **cURL** – Kopieren Sie die Beispielbefehle und ersetzen Sie `sk-your-api-key` durch Ihren tatsächlichen Key
- **Postman** – Importieren Sie unsere [OpenAPI-Spezifikation](/openapi.json)
- **SDK** – Verwenden Sie das OpenAI/Anthropic-SDK mit unserer Basis-URL
</Warning>

## Unterstützte Endpunkte

### Chat & Textgenerierung

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/chat/completions` | POST | OpenAI-kompatible Chat-Completions |
| `/v1/messages` | POST | Anthropic-kompatible Messages-API |
| `/v1/responses` | POST | OpenAI-Responses-API |

### Embeddings & Rerank

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/embeddings` | POST | Text-Embeddings erstellen |
| `/v1/rerank` | POST | Dokumente neu bewerten (Rerank) |

### Bilder

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/images/generations` | POST | Bilder aus Text generieren |
| `/v1/images/edits` | POST | Bilder bearbeiten |
| `/v1/images/generations/{id}` | GET | Pfad für den Bild-Task-Status bei Task-basierten Bildantworten |

<Info>
Einige Bildmodelle geben Ergebnisse inline zurück, andere geben Task-basierte Antworten zurück, und manche verhalten sich je nach geroutetem Provider-Pfad unterschiedlich. Wenn die Erstellungsantwort eine `poll_url` enthält, folgen Sie dieser exakt.
</Info>

### Audio

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/audio/speech` | POST | Text-to-Speech (TTS) |
| `/v1/audio/transcriptions` | POST | Speech-to-Text (STT) |

### Video

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/videos/generations` | POST | Video-Generierungs-Task erstellen |
| `/v1/tasks/{id}` | GET | Asynchronen Task-Status für Video-Jobs abrufen |
| `/v1/videos/generations/{id}` | GET | Legacy-kompatibler Pfad für den Video-Task-Status |

<Info>
Für neue Clients wird `/v1/tasks/{id}` empfohlen; folgen Sie der `poll_url`, die in den Erstellungsantworten zurückgegeben wird. Behalten Sie `/v1/videos/generations/{id}` nur für die Abwärtskompatibilität bei.
</Info>

### Asynchrone Tasks

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/tasks/{id}` | GET | Einheitlicher Endpunkt für den asynchronen Task-Status. Empfohlen, wenn einer zurückgegebenen `poll_url` gefolgt wird |

<Info>
Dieser Endpunkt ist nicht auf Video, Musik und 3D beschränkt. Einige Bild-Tasks verwenden möglicherweise ebenfalls `/v1/tasks/{id}` als kanonischen Polling-Pfad.
</Info>

### Musik

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/music/generations` | POST | Musik-Generierungs-Task erstellen |
| `/v1/music/generations/{id}` | GET | Musikspezifischer Status-Pfad |

<Info>
Für neue Clients wird empfohlen, zuerst die zurückgegebene `poll_url` zu verwenden. Wenn Sie einen festen Endpunkt für den Task-Status benötigen, verwenden Sie `/v1/tasks/{id}`; behalten Sie `/v1/music/generations/{id}` für musikspezifische Kompatibilitätspfade bei.
</Info>

### 3D-Generierung

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/3d/generations` | POST | 3D-Modell-Generierungs-Task erstellen |
| `/v1/3d/generations/{id}` | GET | 3D-spezifischer Status-Pfad |

<Info>
Für neue Clients wird empfohlen, zuerst die zurückgegebene `poll_url` zu verwenden. Wenn Sie einen festen Endpunkt für den Task-Status benötigen, verwenden Sie `/v1/tasks/{id}`; behalten Sie `/v1/3d/generations/{id}` für 3D-spezifische Kompatibilitätspfade bei.
</Info>

### Modelle

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1/models` | GET | Alle verfügbaren Modelle auflisten |
| `/v1/models/{model}` | GET | Spezifische Modellinformationen abrufen |

### Gemini (v1beta)

Unterstützung für das native Google Gemini API-Format:

| Endpunkt | Methode | Beschreibung |
|----------|--------|-------------|
| `/v1beta/models/{model}:generateContent` | POST | Inhalt generieren (Gemini-Format) |
| `/v1beta/models/{model}:streamGenerateContent` | POST | Inhalt per Stream generieren (Gemini-Format) |

<Note>
Gemini-Endpunkte unterstützen zusätzlich zum Standard-Bearer-Token die Authentifizierung über den Query-Parameter `?key=`.
</Note>

## Antwortformat

Alle Antworten folgen einem einheitlichen Format:

### Erfolgreiche Antwort

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1234567890,
  "model": "gpt-4o",
  "choices": [...],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 20,
    "total_tokens": 30
  }
}
```

### Routing-Transparenz

Alle Antworten enthalten ein `_routing`-Feld mit Kanalinformationen:

```json
{
  "id": "chatcmpl-abc123",
  ...,
  "_routing": {
    "channel": {
      "id": "ch_xxx",
      "name": "channel-name",
      "provider": "openai",
      "channelType": "PLATFORM"
    },
    "cached": false,
    "retryCount": 0
  }
}
```

| Feld | Beschreibung |
|-------|-------------|
| `channel.id` | Verwendete Kanal-ID |
| `channel.provider` | Upstream-Provider (openai, anthropic, etc.) |
| `channel.channelType` | `PLATFORM` (LemonData) oder `PRIVATE` (BYOK) |
| `cached` | Gibt an, ob die Antwort aus dem Cache geliefert wurde |
| `retryCount` | Anzahl der Wiederholungsversuche (falls vorhanden) |

### Fehlerantwort

```json
{
  "error": {
    "message": "Invalid API key provided",
    "type": "invalid_api_key",
    "code": "invalid_api_key"
  }
}
```

## Rate Limits

Rate Limits sind rollenbasiert und von Administratoren konfigurierbar. Standardwerte:

| Rolle | Anfragen/Min. |
|------|-------------|
| User | 60 |
| Partner | 300 |
| VIP | 1.000 |

<Note>
Kontaktieren Sie den Support für individuelle Rate Limits. Die genauen Werte können je nach Kontokonfiguration variieren.
</Note>

Wenn Rate Limits überschritten werden, gibt die API einen `429`-Statuscode mit einem `Retry-After`-Header zurück, der angibt, wie lange gewartet werden muss.
