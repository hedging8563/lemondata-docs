## Überblick

LemonData stellt mehrere API-Formate bereit, sodass gängige Coding-Tools, SDKs und Frameworks mit wenig Glue-Code angebunden werden können.

Diese Seite ist bewusst enger gefasst als eine Marketing-Matrix.

- **Unterstützt** bedeutet, dass wir einen konkreten Setup-Pfad dokumentieren und LemonData die dafür benötigte Protocol-Shape bereitstellt.
- **Starker nativer Pfad** bedeutet, dass das Repository direkte Adapter- oder Request-Format-Evidenz für diese Protocol-Familie enthält.
- **Best-effort** bedeutet, dass die Integration funktionieren kann, der Upstream-Client diesen Custom-Gateway-Workflow aber nicht als stabilen Vertrag behandelt.

<Note>
  Nicht unterstützte Felder werden nicht einheitlich behandelt. Auf Kompatibilitätsrouten werden manche Felder ignoriert oder normalisiert. Auf nativen Responses-Routen können explizite `400`- oder `503`-Fehler zurückgegeben werden, wenn das gewählte Modell oder der geroutete Channel das erforderliche Passthrough nicht unterstützt.
</Note>

## Unterstützte API-Formate

| Endpoint | Format | Anwendungsfall |
|----------|--------|----------------|
| `/v1/chat/completions` | OpenAI Chat | Universelle Kompatibilität |
| `/v1/responses` | OpenAI Responses | Zustandsbehaftete Konversationen |
| `/v1/messages` | Anthropic Messages | Claude-native Features |
| `/v1beta/models/:model:generateContent` | Google Gemini | Gemini-native Features |

## IDE- & CLI-Kompatibilität

### Dokumentierte Tool-Pfade

| Tool | Support-Niveau | Format | Hinweise |
|------|----------------|--------|----------|
| **Cursor** | Unterstützt mit Grenzen | OpenAI-compatible | Gedacht für BYOK-Standard-Chat-/Editor-Flows, nicht als Ersatz für Cursor-eigene Funktionen wie Tab Completion |
| **Claude Code CLI** | Starker nativer Pfad | Anthropic | Nativer `/v1/messages`-Pfad mit Adapter-Evidenz für thinking und `tool_choice` |
| **Codex CLI** | Unterstützt, aber modell-/channelabhängig | OpenAI Responses | Am sinnvollsten mit `/v1/responses`; einige Responses-native Felder hängen von nativem Passthrough des Modells / Channels ab |
| **Gemini CLI** | Experimentell / best-effort | Gemini | Der Custom-Base-URL-Workflow mit LemonData ist kein stabiler Upstream-Vertrag |
| **OpenCode** | Unterstützt | OpenAI-compatible | Standardmäßig OpenAI-compatible Provider verwenden; nur bei klarem Bedarf auf einen Responses-Provider wechseln |

<Note>
  Andere OpenAI-compatible Editor- und Agent-Tools funktionieren oft mit demselben Base-URL-Muster, aber dieses Repository pflegt derzeit keine dedizierte Regressionsabdeckung für Windsurf, Aider, Continue.dev, Cline/Roo Code oder GitHub Copilot.
</Note>

### Konfigurationsbeispiele

<Tabs>
  <Tab title="Cursor">
    ```
    Base URL: https://api.lemondata.cc/v1
    API Key: sk-your-lemondata-key
    ```
    Cursor verwendet intern ein Anthropic-ähnliches Tool-Format. LemonData unterstützt beide:
    - OpenAI-Format: `{ type: "function", function: { name, parameters } }`
    - Anthropic-Format: `{ name, input_schema }` (kein type-Feld)
  </Tab>
  <Tab title="Claude Code">
    ```bash
    export ANTHROPIC_BASE_URL="https://api.lemondata.cc"
    export ANTHROPIC_API_KEY="sk-your-lemondata-key"
    ```
  </Tab>
  <Tab title="OpenCode">
    ```bash
    export OPENAI_API_KEY="sk-your-lemondata-key"
    export LOCAL_ENDPOINT="https://api.lemondata.cc/v1"
    ```
  </Tab>
  <Tab title="Aider">
    ```bash
    export OPENAI_API_KEY="sk-your-lemondata-key"
    export OPENAI_BASE_URL="https://api.lemondata.cc/v1"
    aider --model gpt-5.4
    ```
  </Tab>
</Tabs>

## SDK-Kompatibilität

### Dokumentierte SDK- / Framework-Pfade

| SDK / Framework | Sprache | Support-Niveau | Hinweise |
|-----------------|---------|----------------|----------|
| **OpenAI SDK** | Python/JS/Go | Kernpfad unterstützt | Dokumentiert Chat Completions, Embeddings und gängige Responses-Workflows; einige Responses-native-only Felder hängen von Model-/Channel-Passthrough ab |
| **Anthropic SDK** | Python/JS | Starker nativer Pfad | Nativer Messages-Pfad mit direkter Evidenz für tools, thinking und prompt caching |
| **Vercel AI SDK** | TypeScript | Empfohlenes Integrationsmuster | Zuerst `@ai-sdk/openai-compatible`, nur bei explizitem Responses-native-Bedarf `@ai-sdk/openai` |
| **LangChain** | Python/JS | Standardsurface unterstützt | Der beabsichtigte Umfang umfasst `ChatOpenAI` und `OpenAIEmbeddings`; vendor-native Extras sind nicht eingeschlossen |
| **LlamaIndex** | Python | Über `OpenAILike` unterstützt | Für Third-Party-Gateways wie LemonData sollte `OpenAILike` statt der eingebauten OpenAI-Klassen verwendet werden |
| **Dify** | - | Unterstützt mit Grenzen | Gedacht für OpenAI-Provider und chat-completions-orientierte Flows; keine Zusage für Codex-spezifische Responses / WebSocket-Verhalten |

## Chat-Completions-Parameter

### Kernparameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `model` | string | Modellbezeichner (erforderlich) |
| `messages` | array | Konversationsnachrichten (erforderlich) |
| `max_tokens` | integer | Maximale Output-Token |
| `temperature` | number | Sampling-Temperatur (0-2) |
| `top_p` | number | Nucleus-Sampling (0-1) |
| `stream` | boolean | Streaming aktivieren |

### Tool Calling

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get weather for a location",
        "parameters": {
          "type": "object",
          "properties": {
            "location": { "type": "string" }
          }
        },
        "strict": true
      }
    }
  ],
  "tool_choice": "auto",
  "parallel_tool_calls": true
}
```

### Tool-Choice-Optionen

| Format | Beispiel | Beschreibung |
|--------|---------|--------------|
| String | `"auto"`, `"none"`, `"required"` | Einfache Auswahl |
| OpenAI-Objekt | `{ "type": "function", "function": { "name": "fn" } }` | Bestimmte Funktion erzwingen |
| Anthropic-Objekt | `{ "type": "tool", "name": "fn", "disable_parallel_tool_use": true }` | Anthropic-natives Format |

### Erweiterte Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `stream_options` | object | `{ include_usage: true }` für Token-Anzahlen |
| `reasoning_effort` | string | `"low"`, `"medium"`, `"high"` für GPT-5-Modelle mit aktivierter Denkfunktion |
| `service_tier` | string | `"auto"` oder `"default"` |
| `seed` | integer | Deterministische Ausgaben |
| `logprobs` | boolean | Log-Wahrscheinlichkeiten zurückgeben |
| `top_logprobs` | integer | Anzahl der Top-Log-Wahrscheinlichkeiten (0-20) |
| `logit_bias` | object | Token-Bias-Map (-100 bis 100) |
| `frequency_penalty` | number | Wiederholungsstrafe (-2 bis 2) |
| `presence_penalty` | number | Themenstrafe (-2 bis 2) |
| `stop` | string/array | Stop-Sequenzen |
| `n` | integer | Anzahl der Completions (1-128) |
| `user` | string | Benutzerbezeichner für Tracking |

### Erweiterte OpenAI-Features

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `modalities` | array | `["text", "audio"]` für Multimodalität |
| `audio` | object | Audio-Output-Konfiguration (voice, format) |
| `prediction` | object | Vorhergesagter Output für schnellere Completion |
| `metadata` | object | Schlüssel-Wert-Paare für Tracking |
| `store` | boolean | Für späteren Abruf speichern |

### Provider-spezifische Optionen

```json
{
  "anthropic_options": {
    "thinking": {
      "type": "enabled",
      "budget_tokens": 10000
    },
    "prompt_caching": true
  },
  "google_options": {
    "safety_settings": [...],
    "google_search": true,
    "code_execution": true
  }
}
```


## Streaming

Alle Endpoints unterstützen Server-Sent Events (SSE)-Streaming:

```bash
# Chat Completions
curl https://api.lemondata.cc/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -d '{"model": "gpt-4o", "messages": [...], "stream": true}'

# With usage tracking
-d '{"...", "stream_options": {"include_usage": true}}'
```

## Fehlerbehandlung

LemonData gibt OpenAI-kompatible Fehlerantworten zurück:

```json
{
  "error": {
    "message": "Invalid API key",
    "type": "invalid_api_key",
    "code": "invalid_api_key"
  }
}
```

Siehe [Leitfaden zur Fehlerbehandlung](/guides/error-handling) für Details.

## Best Practices

<AccordionGroup>
  <Accordion title="Passthrough für unbekannte Parameter verwenden">
    Alle Schemas verwenden `.passthrough()` - unbekannte Parameter werden an Upstream-Provider weitergeleitet.
  </Accordion>

  <Accordion title="Für genaue Abrechnung `stream_options` bevorzugen">
    Aktivieren Sie `stream_options.include_usage` für genaue Token-Anzahlen in Streaming-Antworten.
  </Accordion>

  <Accordion title="Geeignetes `tool_choice`-Format verwenden">
    Stimmen Sie das Format auf die Erwartungen Ihres SDKs ab. LemonData akzeptiert sowohl OpenAI- als auch Anthropic-Formate.
  </Accordion>
</AccordionGroup>
