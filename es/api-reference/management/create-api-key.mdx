---
## Resumen

Este endpoint crea una nueva API Key de tipo `type=user` dentro de la organización asociada al token de gestión actual.

## Cuerpo de la solicitud

| Campo | Tipo | Valores por defecto / límites | Notas |
|-------|------|------------------|-------|
| name | string | obligatorio, valor por defecto Default Key, longitud 1-50 | Nombre visible, recortado del lado del servidor |
| limitAmount | number \| null | mín. 0, máx. 100000 | null u omitido = ilimitado, 0 = cuota cero, valor positivo = tope en USD |
| models | string[] | por defecto [] | Lista opcional de modelos lógicos permitidos |
| expiresAt | string \| null | fecha y hora RFC3339 | null significa sin expiración |

## Notas

- El valor completo de la API Key solo se muestra una vez en la respuesta.
- `models: []` significa que la clave no tiene restricciones adicionales de modelos más allá de la política de la organización.
- `limitAmount: 0` crea una clave válida pero sin cuota utilizable hasta que se actualice después.

## Ejemplo

<RequestExample>
```bash cURL
curl -X POST "https://api.lemondata.cc/v1/management/api-keys" \
  -H "Authorization: Bearer mt-your-management-token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Backend Worker",
    "limitAmount": 500,
    "models": ["veo3.1", "sora-2"],
    "expiresAt": "2026-12-31T23:59:59Z"
  }'
```
</RequestExample>
