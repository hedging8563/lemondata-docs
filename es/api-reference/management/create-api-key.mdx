## Resumen

Este endpoint crea una nueva API Key `type=user` dentro de la organización asociada al token de administración actual.

## Cuerpo de la solicitud

| Campo | Tipo | Valores por defecto / límites | Descripción |
|-------|------|-------------------------------|-------------|
| `name` | string | obligatorio, valor por defecto `Default Key`, longitud `1-50` | Nombre visible; el servidor recorta espacios al inicio y al final |
| `limitAmount` | number \| null | mínimo `0`, máximo `100000` | `null` u omitido = ilimitado, `0` = cuota cero, valor positivo = tope de gasto en USD |
| `models` | string[] | valor por defecto `[]` | Lista opcional de modelos lógicos permitidos |
| `expiresAt` | string \| null | datetime RFC3339 | `null` significa sin vencimiento |

## Notas

- El valor completo de la API Key solo aparece una vez en la respuesta.
- `models: []` significa que la clave no tiene restricciones adicionales de modelos más allá de la política de la organización.
- `limitAmount: 0` crea una clave válida pero sin cuota utilizable hasta que la actualices.

## Ejemplo

<RequestExample>
```bash cURL
curl -X POST "https://api.lemondata.cc/v1/management/api-keys" \
  -H "Authorization: Bearer mt-your-management-token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Backend Worker",
    "limitAmount": 500,
    "models": ["veo3.1", "sora-2"],
    "expiresAt": "2026-12-31T23:59:59Z"
  }'
```
</RequestExample>
