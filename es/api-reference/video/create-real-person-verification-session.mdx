---
title: "Crear sesión de verificación de persona real"
openapi: "POST /v1/videos/assets/visual-validation-sessions"
description: "Crea una sesión H5 de verificación de material de persona real en TokenLab."
---

Cree una sesión de verificación de corta duración y redirija a su usuario al enlace H5 devuelto. TokenLab devuelve solo campos neutrales: `session_id`, `h5_link`, `callback_url`, `expires_in` y `language`.

La sesión y el enlace H5 caducan después de 120 segundos. El token de vinculación solo lo proporciona el redireccionamiento de callback de TokenLab. Cuando el flujo H5 se completa, TokenLab redirige a su `callback_url` original con estos parámetros de consulta:

| Parámetro | Significado |
|-----------|---------|
| `session_id` | ID de la sesión de verificación de TokenLab. |
| `verification_token` | Token opaco utilizado para vincular el resultado. |
| `verification_status` | `succeeded` o `failed`. |
| `result_code` | Código de resultado para la lógica de su aplicación. |

Si `verification_status` es `succeeded`, llame a [Vincular resultado de verificación de persona real](/es/api-reference/video/bind-real-person-verification-result). La [consola de pruebas](https://tokenlab.sh/dashboard/seedance-assets) puede utilizarse para verificar el manejo de las devoluciones de llamada (callbacks) antes de integrar el flujo en su producto.

## Ejemplo de solicitud

```bash
curl https://api.tokenlab.sh/v1/videos/assets/visual-validation-sessions \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callback_url":"https://yourapp.example.com/seedance/callback","language":"en"}'
```

## Ejemplo de respuesta

```json
{
  "object": "seedance.visual_validation_session",
  "session_id": "svv_abc123",
  "h5_link": "https://verify.example.com/h5?lng=en",
  "callback_url": "https://yourapp.example.com/seedance/callback",
  "expires_in": 120,
  "language": "en"
}
```
